<p>多公网地址配路由器，难点不在填参数，而在决定这些地址怎么分到下游设备上。这篇先讲三种可用的出口结构，再给路由器侧的配置要点，然后是策略路由与端口映射的写法，最后是验证与常见故障。</p>
<h2>一、三种出口结构</h2>
<p>结构一，单 WAN 多地址：一条线进来带多个地址，路由器在 WAN 侧配一个主地址，其余地址通过 NAT 或桥接分配给下游。结构二，多 WAN 单地址，多条线路各带一个地址，做负载或主备。</p>
<p>结构三，桥接模式：路由器只做二层转发，公网地址直接落到下游设备上。三种结构对应不同需求，选错结构，后面怎么配都别扭。</p>

<h2>二、路由器侧的配置要点</h2>
<p>要点一，WAN 侧填主地址、掩码、网关、DNS。要点二，把其余公网地址以“附加地址”或“地址池”的方式加在同一 WAN 上。要点三，为需要独立出口的设备配置一对一 NAT。</p>
<p>一对一 NAT 是关键功能。没有它，多个公网地址只能靠端口映射区分，管理起来非常乱。买路由器前先确认支持一对一 NAT 或 IP 别名。</p>
<h3>掩码与可用地址</h3>
<p>一段 /29 共八个地址，可用六个。扣掉网络地址、广播地址，再扣掉网关，实际能分给设备的更少。算清楚可用数，再决定分几台设备，别做到一半发现不够。</p>
<h2>三、策略路由与端口映射</h2>
<p>策略路由用来指定“哪个源走哪个出口”。写法通常是：源地址段、目标地址、出口接口三要素。配置时注意规则顺序，先匹配先生效，顺序错了规则等于没写。</p>
<p>端口映射用来把外部请求转到内部设备。一对多映射时，不同公网地址映射到不同内部地址的同一端口，可以实现多台设备各自独立对外。</p>

<h2>四、验证与常见故障</h2>
<p>验证三层：路由器能 ping 通网关、下游设备能访问外网、每个公网地址都能在回显页正确显示。第三层最容易被跳过，也最能暴露配置问题。</p>
<p>常见故障：地址冲突（两个设备用了同一地址）、NAT 回环（内网访问自己的公网地址失败）、路由环路（策略路由指向错误接口）。三个都有明确的排查路径。</p>
<h3>改配置的安全顺序</h3>
<p>先备份，再改，改完重启，逐项验证。多人操作时约定同一时间只有一个人改配置，避免互相覆盖。</p>
<h2>五、多地址下的防火墙与安全</h2>
<p>多个公网地址意味着更多的对外入口，防火墙规则要按地址分别写。默认拒绝入站，只开必要的端口，能省掉大量扫描噪音。</p>
<p>管理口不要暴露在公网地址上。远程管理走专用通道或限制来源地址，这是最基本的一条，也是最常被忽略的一条。</p>
<h2>六、文档与交接</h2>
<p>把地址分配、NAT 规则、端口映射整理成一张表，贴在机柜或存进共享文档。换人维护时，这张表能省下几天的摸索。</p>
<p>改动前先备份配置，改动后更新表。两步都做，配置才不会失控。</p>
<h2>常见问答</h2>
<h3>家用路由器能配多个公网地址吗？</h3>
<p>答：多数不能。需要支持多地址绑定或一对一 NAT 的企业级设备。</p>
<h3>桥接模式还需要路由器吗？</h3>
<p>答：桥接后路由器只做交换，公网地址直接落到设备上。需要防火墙时另配。</p>
<h3>多个地址能给同一台设备吗？</h3>
<p>答：可以，设备上配多个地址，或通过 NAT 映射。按用途区分，避免混乱。</p>
<h3>怎么验证每个地址都通？</h3>
<p>答：每个地址单独访问回显页，确认显示一致。批量时写脚本跑一遍。</p>
